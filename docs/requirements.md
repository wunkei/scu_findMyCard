# 四川大学「找卡宝 (FindMyCard)」需求规格说明书 (SRS)

## 1. 文档概述与项目背景

### 1.1 项目背景
在大型高校校园（如四川大学江安校区、望江校区、华西校区），学生与教职工频繁出入食堂、图书馆、教学楼和宿舍，校园卡、身份证、学生证等关键证件遗失与拾获情况极高频发生。
传统校园寻物方式存在诸多痛点：
1. **渠道分散**：失物招领信息散落于 QQ 空间寻物墙、表白墙、微信大群、贴吧，信息沉没率高；
2. **时效性差**：失主无法实时获得通知，往往在补办卡后才看到几天前的信息；
3. **隐私泄露严重**：传统寻物启事常常将失主的真实姓名、完整学号、身份证号甚至手机号直接截图公开发布，极易引发电信诈骗与隐私安全隐患；
4. **位置模糊**：文字描述“在江安一教附近”缺乏精确物理坐标与视觉凭证，拾物人与失主信息不对称。

### 1.2 建设目标
「找卡宝」旨在为四川大学师生提供一个**安全脱敏、即时推送、高精度地理定位、校园认证**的智能卡片失物招领解决方案。通过结合校园认证体系与自动化匹配引擎，打造高效、闭环、值得信赖的校园数字化基础设施。

---

## 2. 参与者与用户角色 (Stakeholders & Actors)

| 角色 | 描述 | 主要职责 |
| :--- | :--- | :--- |
| **认证师生 (失主)** | 经过学号与校园网密码认证的本校在籍人员 | 发布寻卡登记、接收系统智能匹配推送、通过安全信息验证认领失物 |
| **认证师生 (拾获者)** | 拾获他人证件的热心师生 | 录入拾获证件信息、拍摄物品/现场照片、获取高精度经纬度、代管或留原地 |
| **系统核心 (System)** | 自动化匹配引擎与数据保护核心 | 敏感证件规则脱敏、学号/身份证全等碰撞、实时系统级通知推送、本地安全持久化 |

## 3. 功能性需求 (Functional Requirements)

### 3.1 身份认证与权限管理 (FR-01)
- **FR-01.1 极简实名注册**：注册仅需填写「真实姓名」、「川大学号（13位）」和「校园网认证密码」。
- **FR-01.2 校园网 Eduroam 仿真认证**：系统通过安全协议校验学号与密码，校验通过后自动完成校籍绑定。
- **FR-01.3 个人信息中心**：用户可自愿补充完善 18 位居民身份证号（用于身份证拾获自动化匹配）、联系电话与常用校区。
- **FR-01.4 登录态保持与注销**：本地安全存储用户会话，支持一键切换账号或注销退出。

### 3.2 证件信息发布与智能录入 (FR-02)
- **FR-02.1 类型化信息录入**：支持「拾卡」与「寻卡」两种发布场景，覆盖校园卡、学生证、居民身份证、银行卡等主流证件。
- **FR-02.2 高精度 GPS 定位自动化**：
  - 点击发布或打开表单时，系统通过 `LocationHelper` 自动获取当前 GPS/网络定位经纬度；
  - 自动将经纬度反向归类至具体校区（江安/望江/华西）。
- **FR-02.3 现场相机拍照凭证**：
  - 针对「拾卡」流程，强制/推荐拍摄证件当前放置位置的照片；
  - 基于 Android 现代 `FileProvider` 安全机制生成内容 URI 并持久化存储。
- **FR-02.4 状态定义**：明确区分卡片放置状态（“还在原地” / “由发布者代为保管”）。

### 3.3 严格数据脱敏与隐私保护规范 (FR-03)
为了阻断任何潜在的信息泄露与黑产盗用，系统在所有公共信息流（首页、发现页、信息大厅）中执行严格的字段级展示规则：
1. **姓名脱敏**：
   - 2个字姓名：只显示末位字符（如：`*四`）；
   - 3个字姓名：显示首末位字符，中间遮蔽（如：`张*丰`）；
   - 4个字及以上姓名：显示首末位，中间遮蔽全部（如：`诸**明`、`买*****逊`）。
2. **证件号码脱敏**：
   - **居民身份证**：仅显示前 6 位与后 2 位（如：`110101**********75`）；
   - **校园卡/学生证**：仅显示前 4 位与后 3 位（如：`2023******001`）；
   - **其他证件**：仅显示前 2 位与后 2 位（如：`EB*****67`）。
3. **公共流备注彻底屏蔽**：从公共发现页卡片中移除完整补充备注（note），防止拾获者误将电话或全名填入备注造成二次泄露。

### 3.4 智能碰撞匹配与系统级通知推送 (FR-04)
- **FR-04.1 自动碰撞算法**：当任一用户发布新的「拾卡」信息时，匹配引擎 `MatchNotificationHelper` 自动将帖子中的证件号与系统当前认证用户的实名证件号（学号、身份证号）进行精准碰撞匹配。
- **FR-04.2 专属高优先级通知**：
  - 若证件号与当前登录用户的学号或身份证完全一致，系统立即发出 Android 系统级高优先级（`IMPORTANCE_HIGH`）通知；
  - 通知标题明确提示：“🎉 找到了属于您的卡片！”，正文提示拾获校区与位置，点击即可一键唤醒应用直达详情。

### 3.5 发现页检索与地图导航联动 (FR-05)
- **FR-05.1 多维度条件过滤**：支持按校区（江安/望江/华西/全部）、发布类型（全部/寻卡/拾卡）进行实时流式筛选。
- **FR-05.2 精确检索**：搜索框支持失主姓名与完整证件号码匹配检索。
- **FR-05.3 地图导航跳转**：若帖子带有经纬度坐标，卡片显示「⌖ 导航」按钮，点击通过通用 Geo Intent（`geo:lat,lng`）拉起高德地图/腾讯地图/百度地图进行路线导航。
- **FR-05.4 现场原图弹窗查看**：若帖子附带现场照片 URI，用户可点击全屏弹出查看现场物品细节。

## 4. 非功能性需求 (Non-Functional Requirements)

### 4.1 健壮性与输入校验 (Robustness)
- 身份证校验必须严格满足中华人民共和国国家标准《公民身份号码》(GB 11643-1999) 的 **ISO 7064:1983.MOD 11-2** 加权模运算校验码逻辑。
- 手机号严格遵循 11 位大陆规范（`1[3-9]\d{9}`）。
- 学号严格校验 13 位纯数字，且前 4 位入学年份必须在合理学制区间（2000 年至当前年份）。

### 4.2 性能与流畅度 (Performance)
- UI 基于 Jetpack Compose 现代声明式架构与 Kyant Backdrop 高级玻璃拟态渲染，帧率稳定在 60fps/120fps。
- 数据库检索采用 SQLite 索引优化与异步协程（Kotlin Coroutines + Flow），UI 线程零阻塞。

### 4.3 安全性与合规性 (Security)
- 敏感证件信息脱敏展示；
- 拍照文件仅通过应用沙箱 `FileProvider` 授权访问，禁止向外部公开私有文件物理绝对路径；
- 敏感权限（定位、相机、通知）遵循 Android 13+ 运行时动态请求规范。

### 4.4 可维护性与可测试性 (Maintainability & Testability)
- 代码遵循 Google 官方 Recommended Architecture for Android Apps；
- 核心业务逻辑（校验、匹配、脱敏）抽离为纯 Kotlin Domain 层，单元测试覆盖率达到 100%。
